# ADR 0004: License TemperedOps Creator Toolkit under AGPL-3.0-only

- Status: Accepted
- Decision date: 2026-07-28

## Context

TemperedOps Creator Toolkit is an open-source-first network application intended
to be self-hosted and modified. The project should guarantee recipients the
usual software freedoms and ensure that operators who provide a modified
version over a network offer its corresponding source to those users.

The project also needs an unambiguous SPDX expression for source files,
dependency review, repository metadata, and automated license tooling.

## Decision

License original TemperedOps Creator Toolkit project material under the GNU
Affero General Public License version 3 only, using the SPDX identifier:

```text
AGPL-3.0-only
```

The root `LICENSE` contains the canonical license text. Original project
documentation and future source headers use `AGPL-3.0-only`, not
`AGPL-3.0-or-later`. Adapted or bundled third-party material retains its
applicable license and attribution and identifies that license separately.

Contributions are accepted under the same project license without a contributor
license agreement unless a later governance decision explicitly changes that
process. Dependencies and bundled assets must have terms compatible with
distribution of the combined project under AGPL-3.0-only.

Future interactive releases must provide an appropriate legal notice and a
prominent way for remote users to obtain the corresponding source for the
running version.

## Consequences

Benefits:

- users may inspect, run, modify, and share the application;
- network users of modified deployments receive the source-access protection
  relevant to a web application;
- a precise SPDX identifier supports automated compliance;
- improvements to publicly operated modified versions remain available under
  the license's conditions.

Costs and constraints:

- some organizations and contributors may avoid strong copyleft software;
- dependency and asset compatibility needs deliberate review;
- distributors and modified network operators have corresponding-source and
  notice obligations;
- “only” means later AGPL versions do not automatically apply.

This ADR records a project policy, not legal advice.

## Alternatives considered

- **MIT or Apache-2.0:** simpler permissive reuse but rejected because modified
  hosted versions could remain closed.
- **GPL-3.0-only:** strong copyleft on conveyed copies but lacks AGPL's specific
  remote-network interaction provision.
- **AGPL-3.0-or-later:** rejected because the project requires an explicit
  version 3-only commitment.
- **Dual or commercial licensing:** rejected for the initial community project
  because it adds governance and contributor-rights complexity.

## Revisit when

Any license change requires maintainer and contributor-rights analysis and a new
ADR. Existing contributions cannot simply be relicensed without the necessary
permissions.
